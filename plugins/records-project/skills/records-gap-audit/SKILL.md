# Gap audit

A full re-read of a records project hunting for what is missing rather than summarising what is there.

## ⚠️ Read the Settled register first — this is the whole discipline

Before hunting for anything, read `01 Master/Settled — do not re-open.md` **in full**.

Then, for every candidate gap you find, ask **"has this already been answered?"** before writing it down:

1. Is it in the Settled register? → **not a gap.**
2. Does a *later* document already resolve it? → **not a gap.** A concerning value from March may have been rechecked and resolved in June. Read forward before flagging.
3. Did the person already explain it in a previous chat? → **not a gap.** Grep the Prompt Log and the chronicle for the term.

**A wrongly-raised gap is worse than a missed one.** It costs the person time re-explaining something they've settled, and it erodes trust in the whole audit. If you are not sure whether something was addressed, say so explicitly rather than asserting it wasn't.

**"No new gaps" is a valid and useful result.** Say it plainly when it's true rather than manufacturing findings to seem thorough.

## What to actually read

Everything, in this order: `CLAUDE.md` → Settled register → Master Summary → all question lists → Timeline → Prompt Log → every file in the chronicle → trend tables → critiques → prior gap audits. **Read prior audits carefully** — repeating a finding they already retracted is the characteristic failure of this skill.

## What to hunt for

**Unaddressed findings.** An abnormal value or notable observation that appears once and is never mentioned again — no follow-up, no recheck, no plan. Check whether a later panel answered it.

**Overdue follow-ups.** Something scheduled or promised that has no result on file. "We'll recheck in six weeks" with nothing six weeks later.

**Contradictions.** The same fact stated differently in two places — dates, doses, values, histories. Also: advisors who disagree without the disagreement ever being resolved or even acknowledged.

**Unowned items.** Something everyone assumes someone else is handling. Named owner missing.

**Stale "pending".** Items recorded as awaiting a result that were never actually performed — the distinction between *pending* and *not done* matters and is easy to lose.

**Mentioned once, then dropped.** A symptom, a concern, or a goal raised early and never returned to. Stated goals are worth checking specifically: is anything in the plan actually serving them?

**Never assessed at all.** Areas relevant to the situation that appear nowhere in the record. Absence is harder to see than error.

**Routine maintenance** appropriate to the domain that isn't tracked anywhere.

## How to report

Write to `07 Deep Dives/YYYY-MM-DD Gap Audit.md`. For each gap:

- **What is missing**, in one sentence.
- **Evidence** — which files, which dates. Cite specifically enough to be checked.
- **Whether it is genuinely new**, and how you confirmed that.
- **Cheapest next step**, and **who owns it**.
- **Consequence if ignored** — this is what makes tiering meaningful.

**Tier by consequence, not by how interesting it is.** Something dull and overdue usually outranks something novel and speculative.

Then: add the real ones to the appropriate question lists, add a Timeline row and a Prompt Log entry, and follow the project's snapshot rule.

## Framing

The decision-maker is named in `CLAUDE.md` and may not be the person reading this. Respect the conservatism dial: an audit is for surfacing what's unaddressed, not for advocating intervention. Present each gap with options and let the decision-maker decide.

If a previous audit of yours got something wrong, **say so explicitly and record the retraction** — in the audit and in the Settled register. That is how the register earns its keep.
